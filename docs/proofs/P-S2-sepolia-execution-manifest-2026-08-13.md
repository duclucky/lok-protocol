# P-S2 Sepolia Execution Manifest

**Status: PROPOSED / READ-ONLY / NOT AUTHORIZED.**

No transaction, deployment, public-decryption request, relayer request that can create a Gateway transaction, or ETH
spend is authorized by this document. Group A and Group B require separate owner approval of both the transaction list
and the ETH cap. Any change to an approved list or cap requires renewed approval.

## Basis And Hard Stops

- Frozen source: `docs/10-proof-strategy.md` section 3, P-S2. This document does not edit or reinterpret that row.
- Code/test commit: `65ff43262778a1c073d1d2f413a11d9c57cb98a5`.
- Planning evidence commit: `5dc9ec06742a19318799fca96c9727b9aa6eddaf`.
- Network: Ethereum Sepolia, chain ID `11155111`.
- Read-only snapshot: block `11479695`; operator `0x8e7939E23a012143e5182d7173DAD42B2006c2b8`; balance
  `0.320904470408082305 ETH`; observed max fee `2.163886296 gwei`.
- Numeric aggregate assets, liabilities and principal must never be decrypted. Only the frozen checkpoint-specific
  aggregate `isSolvent` boolean may be publicly decrypted.
- Stop immediately on an unexpected receipt status, protected-state mutation, API behavior, bytecode mismatch, HCU
  failure, or gas/HCU deviation greater than 50% from its evidence basis. Do not improvise a replacement transaction.
- The historical 54-transaction/`0.16 ETH` sketch in `artifacts/sepolia/p-s2-preflight.json` is superseded for approval
  purposes by this manifest because it omitted several transition-specific Sepolia checks.

Gas figures below are per-transaction planning ceilings, not promises. The draw ceilings use the actual draw #1
receipts: `preSyncA` up to `1,855,454`, `crankA` up to `2,163,809`, `crankB` up to `1,631,934`, and settlement was
`1,631,934` gas. Deployment ceilings use the actual canonical deployments with a 25-35% margin. The total hard gas stop
can be lower than the sum of all independent per-transaction ceilings because those ceilings cannot all be
simultaneously worst-case.

## State And Recovery Codes

| Code | State/custody effect                                                                                        | Rollback or recovery                                                                                                         |
| ---- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `N`  | Public configuration, cursor or proof state only; no direct custody movement.                               | A reverted call is identity. Successful draw/checkpoint state is advanced only by the listed next step.                      |
| `M`  | Mints demo-backed cUSDC to the operator or funded yield to an adapter.                                      | Test principal is recovered through withdrawal/exit. Funded yield is irreversible once allocated to a draw.                  |
| `D`  | Moves confidential principal between operator, vault and adapter and updates encrypted accounting.          | `withdrawAll`, `emergencyWithdraw`, or `exit/finalizeExit`, as explicitly listed.                                            |
| `Y`  | Harvests funded yield and allocates encrypted direct/prize credits.                                         | No rollback. If PASS B has started, recovery is permissionless completion; abort is forbidden after the first PASS-B credit. |
| `R`  | Changes the active/retiring custody boundary and `riskEpoch`.                                               | No rollback. Recovery is drain, current-epoch true checkpoint, removal, and final checkpoint.                                |
| `F`  | Expected revert; protected state and custody must be byte-for-byte/public-state identical before and after. | None required. Any mutation is a counterexample and stops execution.                                                         |
